### 3.3 nginx 配置的两个坑

**坑一：`add_header` 在 location 里出现会导致 server 级全部失继承。**
nginx 的规则是"子级一旦有自己的 `add_header`，父级的就不再合并"。所以：

- 所有安全头**只写在 server 级**；
- 缓存策略一律用 `expires` 指令（它生成 `Cache-Control`，不属于 `add_header`，不破坏继承）。

曾以此踩过：首页只剩 `X-Content-Type-Options`，CSP / HSTS / Referrer-Policy 全丢。

**坑二：`server_tokens off` 才让 `Server` 头退回 `nginx`。** 默认会暴露版本号。

当前配置要点：CSP 允许 `'unsafe-inline'`（整站内联）、`connect-src` 白名单只含
`count.hongxian.dev`；`www` 与 apex 同 server 块（不重定向，两者都出 200）。

### 3.4 证书

```bash
# DNS 指向本机后（先确认 dig +short hongxian.dev 返回 <HOST_IP>）
sudo certbot --nginx -d hongxian.dev -d www.hongxian.dev --agree-tos -m <EMAIL> --redirect
```

certbot 自带 `certbot.timer` 自动续期（`systemctl list-timers | grep certbot` 可查）。
续期后需要 reload nginx，`/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` 放一行 `systemctl reload nginx`。

## 4. 平台服务（预发）

### 4.1 首次部署

```bash
sudo apt install -y docker.io docker-compose-v2
sudo usermod -aG docker ubuntu          # 重新登录生效
git clone https://github.com/hongxian-dev/hongxian.git /opt/hongxian/repo
cd /opt/hongxian/repo/packages/server

mkdir -p data && sudo chown 1000:1000 data   # 见 4.2 坑
printf 'HONGXIAN_INSTANCE=prestage.hongxian.dev\n' > .env   # .env 已 gitignore

sudo docker compose up -d
sudo docker compose ps
curl -s http://127.0.0.1:8787/healthz
```

### 4.2 唯一必踩的坑：数据目录属主

镜像里 `USER node`（uid 1000），Dockerfile 也 `chown node:node /data`。
但 compose 的 `./data:/data` 是 **bind mount**，会覆盖镜像内那层属主，
宿主机上由 docker 建的 `data/` 属主是 `root` → 容器启动即：

```
Error: EACCES: permission denied, mkdir '/data/identities'
```

修法就是上面那句 `chown 1000:1000 data`。**不要**改成 `user: root` 绕过——
那会让零知识服务以 root 写密文库，得不偿失。也不要用 named volume——
bind mount 让运营者能直接看到"就是一堆密文文件"，这是零知识叙事的一部分。

### 4.3 预发为什么真的摸不到

- compose 端口写死 `127.0.0.1:8787:8787`（不是 `8787:8787`）；
- nginx 不反代 8787，防火墙不放开 8787；
- 访问方式只有 SSH 隧道：

```bash
ssh -L 8787:127.0.0.1:8787 ubuntu@<HOST_IP>
# 然后本地开 http://127.0.0.1:8787/healthz
```

验证确实封闭：从外部 `curl http://<HOST_IP>:8787/healthz` 必须连不上。

### 4.4 预发验收

```bash
# 本机（隧道已开）
node packages/server/e2e/smoke-remote.mjs http://127.0.0.1:8787
# 或 npm run smoke:deployed --workspaces=false -- http://127.0.0.1:8787
```

29 项，覆盖：healthz / 四军规（无 `/match` `/recommend` `/search`）/ 注册与重注冲突 /
公钥形状校验 / 贴卡与拉取 / **广场响应不含 key_l1** / 卡验签 / 投递与拉信箱 /
信体验签与正文还原 / 未认证 401 / 举报与自举报拒绝 / 举报汇总仅本人可查 /
stats 不含任何 opaque ID / 注销级联清零。

**它与 `npm run e2e:server` 的分工**：后者 spawn 本地进程验代码；前者只走 HTTP 验部署
（容器起没起、卷能不能写、反代或中间件有没有破坏零知识链路）。两者都要跑。

### 4.5 日志与运维命令

```bash
cd /opt/hongxian/repo/packages/server
sudo docker compose logs --tail 100 -f
sudo docker compose restart
sudo docker stats --no-stream             # 空闲约 30MB / CPU 0%
sudo du -sh data                          # 空库约 28K
```

### 4.6 升级到新版本

```bash
cd /opt/hongxian/repo
git fetch origin && git reset --hard origin/main
cd packages/server && sudo docker compose up -d --build
```

数据在 bind mount 里，重建容器不丢。**备份就是 `cp -r data`**。

## 5. DNS 与切换

`hongxian.dev` 托管在 Cloudflare（Registrar + DNS）。切换 apex 需改 A 记录：

| 记录 | 迁移前 | 迁移后 |
|---|---|---|
| `A @` | GitHub Pages 四条 185.199.108–111.153 | 一条 `<HOST_IP>`，**DNS only（灰云）** |

**必须灰云**：橙云（代理）会接管 TLS，导致 certbot HTTP-01 验证被 Cloudflare 拦截，
且 nginx 侧只能看到 CF 的 IP。要么全程灰云，要么改走 CF 的 Origin Certificate。

`www` 原为 CNAME → apex，改 apex 后自动跟随，无需单独处理。
`count.hongxian.dev` 是 Worker 自定义域（橙云），与 apex 无关，不受影响。

### 回滚

把 `A @` 改回四条 GitHub Pages IP 即可，Pages 侧配置一直保留未动。
切换前把 TTL 调到 60 秒，回滚窗口就是 1 分钟。
