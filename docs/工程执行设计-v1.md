## 2. Monorepo 结构

技术详设 §3 结构落地（pnpm → **npm workspaces**，环境无 pnpm；workspace 协议 npm 原生等价）：

```
D:/7-sunchao资料/红线项目/
├── package.json              # workspaces 根 + 全局脚本（build/test/verify）
├── tsconfig.base.json        # 严格模式共享配置
├── LICENSE                   # Apache-2.0（v1 清单 §3 拍板）
├── README.md / README.en.md  # 产品三：安装 ≤3 步、哈希核对、信任清单、FAQ、协议链接
├── packages/
│   ├── schema/               # @hongxian/schema —— 协议 v0 的机器可读形态（Zod）
│   ├── crypto/               # @hongxian/crypto —— 密钥体系（Ed25519/X25519/AES-GCM/Argon2id/BIP39）
│   ├── core/                 # @hongxian/core   —— 领域逻辑（纯函数，零 IO）
│   └── mcp/                  # @hongxian/mcp    —— 月老 MCP Server（薄壳 + 存储适配层）
├── apps/
│   ├── web/                  # 已交付（产品二）
│   └── counter/              # 已交付（透明数据后端）
└── docs/
    ├── protocol-v0-spec.md   # 产品三：协议规范 v0 草案（CC-BY-SA 4.0）
    ├── host-compatibility.md # W7：宿主兼容性矩阵
    └── install-and-trust.md  # 安装指引 + 信任清单全文（README 的展开版）
```

**依赖方向**（单向，杜绝环）：`mcp → core → {schema, crypto}`；`schema`、`crypto` 互不依赖。

## 3. 关键设计决策（在技术详设基础上的本轮拍板）

### E1 · 本地存储 = 纯 JSON 文件 + 内存索引，不用 better-sqlite3

- **理由**：技术详设 §2 自述"纯 JS、无原生依赖（跨平台安装零摩擦）是加密选型的第一原则"——better-sqlite3 恰恰是原生依赖，且技术详设 §9 风险①自认"部分用户环境编译失败"。数据本体本就是 JSON 信封文件，SQLite 只做索引加速；v1 数据量（数百信封级）内存索引完全够用。
- **实现**：`core` 定义 `Store` 接口（纯逻辑）；`mcp` 包提供 `FsStore`（node:fs + path，全程 NFC 归一化，应对 Windows 中文路径——技术详设 §9 风险⑥）。索引 = 启动时扫描目录重建。**预留迁移位**：`node:sqlite`（Node 22+ 内置）作为未来可选项，v1 不引入。
- **wipe 验收**（清单 §1"一键删除无残留"）：wipe = 递归删除 `~/.hongxian/` 全目录 + 返回删除清单，测试断言磁盘零残留（含临时文件）。

### E2 · 构建与测试 = tsc（严格）+ Vitest，无打包器

- 每个包 `tsc -p tsconfig.json` 产出 `dist/`（ESM，`"type": "module"`）；vitest 直接跑 TS 源码。
- 不用 tsup/esbuild：发布物可审计性优先（信任清单第 1 条"读源码"——构建步骤越少，源码与产物越可对应）。
- 测试三层：**单测**（每包）→ **集成**（core+crypto 信封全链路）→ **E2E**（真实 STDIO 子进程跑 MCP 协议握手 + 建画像→签卡→导出→导入→比对全流程）。

### E3 · 许可拍板（v1 清单开放问题 #4）

- **代码**：Apache-2.0（v1 清单 §3 已定；对采用最友好，兑现"全力成为协议标准"）
- **协议规范文档**：CC-BY-SA 4.0（规范类文档惯例：W3C/CC 系；保证规范派生开放，且与代码许可分离——协议本身不应被 Copyleft 代码许可绑架）

### E4 · MCP SDK 用法 = 高层 `McpServer` API（registerTool / registerPrompt）

- 低层 `Server.setRequestHandler` 手写 schema 冗长易错；高层 API 内建 Zod 校验，与 schema 包同源。
- STDIO transport（技术详设 §2）。**所有日志走 `console.error`**，stdout 只许协议帧（STDIO 铁律）。

### E5 · 密钥流程细节（技术详设 §4 的工程参数）

- BIP39：**中文简体词表 24 词**（`@scure/bip39` wordlists/chinese-simplified）
- Argon2id 参数（哈希前向兼容）：`t=3, m=64MB(65536), p=4`，输出 32 字节 → MK
- 派生路径（技术详设 §4）：MK → 加密 `identity_seed`/`kx_seed`/`layer_keys` 三个文件（id.enc/kx.enc/lk.enc）
- 加密文件格式：`{"salt": b64, "nonce": b64, "ct": b64, "algo": "argon2id+aes-256-gcm"}`（盐随机 16 字节，nonce 12 字节）
- MK 生命周期：仅存解锁会话内存；`lock` 工具 / 进程退出即覆写清零（Buffer.fill(0) + GC 提示）
- **v1 不接 OS keychain**（技术详设 §4 的可选项）：keychain 涉及平台 API 与额外权限，违背"安装零摩擦"；v1 策略 = 宿主会话内 MK 缓存 + 可配置超时自动锁定。keychain 记入 v2。

### E6 · 加密信封实现口径（Schema v0.3 §2/§6）

- 签名：Ed25519 over `canonical_json(meta || payload_L1_ct || payload_L2_ct || payload_L3_ct)`（**JCS 规范化 JSON**，防序列化差异）
- AEAD：AES-256-GCM（@noble/ciphers），nonce 12 字节随机，tag 16 字节
- 层密钥分发：grant_l2/grant_l3 = 用**收件人 X25519 公钥** ECDH → HKDF-SHA256 → AES-GCM 封装对应层密钥（"换卡即换公钥"）
- key_L1 **随卡明文携带**（Schema §8 拍板①：L1 也加密，格式三层统一）
- 名片文件扩展名 `.hongxian-card`；信封文件 `.hongxian-env`

### E7 · 计数上报边界

- `mcp` 包内置 `reportMetric(metric)`：读 `settings.json` 的 `opt_in_counter`（**默认 false**）→ false 时**零出网**（验收：抓包关闭 opt-in 后出网为零）
- true 时 POST `count.hongxian.dev/bump`（4s 超时、失败静默、不重试、不入日志）
- Worker 侧已交付（apps/counter），口径见《产品网站与透明统计v1设计初稿》

### E8 · MCP tools 与 D 编号映射（12 tools 全功能，无裁剪）

| Tool | 职责 | 决策依据 |
|---|---|---|
| `interview` | 渐进访谈状态机推进 + 复述确认稿生成 + 落盘 | D1 |
| `sign_card` | 组装三层 payload → 逐层加密 → 签名 → cards/mine/ | D5/S4 |
| `export_card` | 导出 .hongxian-card 文件 + QR（哈希确认码） | S5 |
| `import_card` | 验签 → TTL 检查 → 入库 contacts/ | S5 |
| `compare` | 粗筛（零 token）+ 报告输入组装（叙事交宿主 LLM） | D6/S6 |
| `send_envelope` | 九类信封工厂出口（upgrade/topic/answer/graduation/decline…） | D3/D10/D13 |
| `receive_envelope` | 信封入口：验签 → 路由 → 状态机推进 | D3/D11 |
| `ledger` | 姻缘线列表 / 拉黑（3 次未回应规则）/ 手账 | D3②/D15④⑥ |
| `coach` | 选题教练：候选题 + 出题理由 + 伦理护栏过滤 | D12 |
| `backup` | 加密档案导出（恢复短语由首次流程强制，backup = 档案文件） | D15③ |
| `restore` | 加密档案导入 + 恢复短语重解锁 | D15③ |
| `wipe` | 一键删除全部本地数据（无残留验收项） | S3/清单§1 |

**4 prompts**：`yuelao_persona`（人格与禁令，D2）/ `interview_flow`（三次访谈指引，D1）/ `report_narrative`（五档三区叙事规范，D6）/ `coach_ethics`（选题教练伦理护栏，D12）。

### E9 · core 纯函数模块与技术详设 §3 对齐

| 模块 | 职责 | 关键规则 |
|---|---|---|
| `profile/` | 访谈状态机（3 阶段）、复述确认、dealbreakers、completeness 计算 | D1；复述未确认不落盘 |
| `card/` | 信封工厂：组装/加密/签名/验签/重签/TTL | Schema §2/§7；验签失败整卡作废 |
| `match/` | 粗筛算法（结构化规则，零 token）+ 报告输入组装 | D6/D7；硬伤命中→档位封顶 |
| `rounds/` | 轮次状态机：主题→追问→回卷→增量输入 | D11；追问 ≤2；饱和度跟踪 |
| `ledger/` | 姻缘线状态机 + 拉黑规则 | D15④：3 次未回应→建议拉黑 |
| `filter/` | 出站授权过滤 + 题目泄露面审查 | D9/D15⑦：敏感题中性化代问 |
| `guard/` | 防注入：外来内容数据标记 + 指令隔离 | 技术详设 §9 风险③ |

## 4. 测试策略（可靠性的证明）

| 层 | 工具 | 覆盖 |
|---|---|---|
| 单测 | Vitest | schema 全部字段规则 + 容错（未知字段/TTL/完整性）；crypto 全流程 + 互操作（A 签 B 验）；core 每模块规则（dealbreaker 封顶/追问封顶/3 次拉黑/复述门闩） |
| 集成 | Vitest | 信封工厂全链路：建→签→导→导回→验→比对；grant_l2 密钥交付后 L2 可解、交付前不可解 |
| E2E | 子进程 STDIO | 真实 MCP 协议握手：initialize → tools/list(12) → prompts/list(4) → interview→sign_card→export_card→import_card→compare 全流程 |
| 自证 | 脚本 | ① 零外链：grep 全仓库源码无跟踪域名（除计数器端点）② wipe 无残留 ③ 关闭 opt-in 零出网（静态审计） |
