# 匹配卡 Schema 规范

> 本文档是红线协议规范 v0 的核心章节，也是《v1产品清单与验收标准》W1 的前置交付物。
> 上位约束：《红线项目定位声明》v0.6（邮局四军规、数据主权军规、D5 三阶阶梯、D7 成本归属、D10 考题卡、D13 见面层 opt-in）。
> 状态：v0.3 定稿（2026-10-14，盲区扫描补丁：补性别字段与成年承诺；随协议规范 v0 一并公开）。

---

## 1. 设计原则（六条，全部继承自已定稿的决策）

1. **三阶阶梯 = 三层加密**（D5）：公开层 / 匹配层 / 私密层，物理隔离于三个独立加密 payload，不存在"一张明文卡靠权限控制"的设计
2. **对称互换是 schema 约束**（D5 铁律）：匹配层与私密层的解锁密钥交换动作天然双向——你给我密钥的同时我给你密钥，结构上防单向窥探
3. **私密层逐一 opt-in**（D13）：每个字段独立加密、独立开关，支持"给微信号不给手机号"
4. **永不收集**（军规）：身份证号、精确住址（到小区以下）、精确收入数字（只收"段"）、聊天记录——任何一层都不设字段
5. **弱模型友好**（D7）：字段以受控枚举为主、自由文本设长度上限并夹在 schema 里，弱模型也能产出合格卡片；卡片强制带画像深度标记，供对方标注置信度
6. **v1→v2 零迁移**（D8/D12 广场）：payload 格式从第一天就按"服务端零知识"设计——服务端只见元数据与密文，广场贴卡无需任何格式变更

## 2. 信封结构（Envelope）

一张匹配卡 = 一个 JSON 文件：

```
MatchCard Envelope
├── meta        明文元数据（任何人可读）
├── payload_L1  公开层密文（AES-256-GCM，key_L1）
├── payload_L2  匹配层密文（AES-256-GCM，key_L2）
├── payload_L3  私密层密文（AES-256-GCM，key_L3，可整体缺省）
└── signature   Ed25519 签名（对 meta + 三个密文整体签名）
```

### meta 字段（明文）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `schema_version` | int | 当前 `1` | 向前兼容：未知字段必须忽略，不报错 |
| `card_id` | UUIDv7 | 全局唯一 | opaque，不含任何身份信息 |
| `owner_key_id` | base64 | 32 字节指纹 | 签名公钥指纹，非身份信息 |
| `version` | int | 单调递增 | 画像更新后重签，旧 version 自动作废 |
| `created_at` / `expires_at` | ISO 8601 | TTL 默认 30 天 | 到期需续签（D8 广场贴卡防僵尸信息；v1 名片同样适用） |
| `card_type` | enum | `match_card` / `plaza_card`(v2) | 名片卡 / 广场贴卡 |
| `depth` | object | 必填 | **画像深度标记**（D7）：`interview_rounds`（访谈轮数）、`completeness`（字段完整度 0–1）、`model_tier`（local/cloud，声明级别不声明型号） |
| `introducer_sig` | ~~可选~~ **已废弃** | 介绍人签名 | **2026-10-20 废弃**：介绍人链随 D8 修订（分发半径唯一模型=声明式圈层）整体裁撤；字段编号保留不复用，实现端忽略该字段 |
| `algo` | object | 固定 | `{"sig":"ed25519","aead":"aes-256-gcm","kex":"x25519"}` |

## 3. 三层 Payload 字段表

约定：**enum 值域见第 5 节受控词表**；所有枚举字段允许 `unspecified`（未回答也是合法值，且与"婉答"区分）。

### 3.1 Payload L1 · 公开层（名片层）

| 字段 | 类型 | 约束 |
|---|---|---|
| `nickname` | string | ≤20 字 |
| `gender` | enum | `female` / `male`（v0.3 补，v0.2 遗漏——匹配最低必要字段） |
| `seeking` | enum | 寻找对象性别：`female` / `male`（v0.3 补。技术上不限制组合，v1 产品引导以严肃婚恋异性匹配为主——这是产品引导决策，不是 schema 限制） |
| `age_attested` | bool | 成年承诺（≥18 周岁），必填 true 才可签发（v0.3 补，未成年人保护法律要求） |
| `age_band` | enum | 年龄段（如 `26_30`），**不收精确出生日期** |
| `city` | enum+string | 市级行政区代码 |
| `height_band` | enum | 身高段 |
| `marital_status` | enum | `never_married` / `divorced_no_child` / `divorced_with_child` / `widowed` |
| `job_category` | enum | 职业大类 |
| `education_band` | enum | 学历段 |
| `interests` | string[] | ≤5 个，受控词表 |
| `bio` | string | ≤100 字一句话介绍 |
| `goal` | enum | `serious_dating` / `marriage_oriented` |
| `econ_signal` | enum 可选 | **经济状态自述**（v0.2 新增，孙超提议）：`undisclosed`(默认) / `independent`(经济独立) / `home_owner`(有房) / `home_owner_no_mortgage`(有房无贷) / `car_owner`(有车) / `multi`(多项，自由组合数组)。形态为"生活状态"而非收入数字——满足初筛时的经济基本面诉求（孙超：陌生人之间比较关注对方的经济条件），同时不构成公开的精确收入筛选器（反诈：杀猪盘按收入条件筛选目标） |

### 3.2 Payload L2 · 匹配层（深聊层）

| 字段 | 类型 | 约束 |
|---|---|---|
| `values_tags` | object[] | 受控词表标签 + 权重（0–1），≤8 个 |
| `lifestyle` | object | 受控枚举：作息类型 / 吸烟 / 饮酒 / 运动频率 / 社交频率 |
| `family_view` | object | 与父母关系（enum）+ 生育意愿（段）+ 是否与父母同住意愿（enum） |
| `money_view` | enum | 消费倾向五档（精打细算↔体验优先），**不收收入数字** |
| `assets_brief` | object | 房 / 车：`owned` / `not_yet` / `indifferent_to_partner`，各自独立 |
| `income_band` | enum 可选 | 宽区间段（如 `10_20w`），**可整字段缺省** |
| `dealbreakers` | object[] | **负面清单**：维度（enum）+ 描述（≤50 字），≤5 条 |
| `values_qa` | object[] | 3–5 段价值观问答原文（问题 + 回答，各 ≤200 字）——报告引用原话的证据源（D6） |
| `partner_pref` | string | ≤150 字对理想对象的描述 |

### 3.3 Payload L3 · 私密层（见面层，整体可缺省）

| 字段 | 类型 | opt-in 默认 |
|---|---|---|
| `contact_wechat` | string | **开**（D13 默认推荐） |
| `contact_phone` | string | **关** |
| `real_name` | string | 关 |
| `employer_category` | enum | 关（工作单位大类，不收精确单位名） |
| `hangout_areas` | string[] | 关（常去区域，到商圈为止） |
| `photo_refs` | object[] | 关（**照片不进卡**：仅存本地密文文件的哈希 + 解密密钥，原图经同一信道另行传输——防卡片文件转发导致照片扩散） |

## 4. 信封类型族（协议 v0 的消息类型）

同一信封格式 + `card_type`/`msg_type` 区分，全部走 D3/D11/D13 的握手信道：

| 类型 | 方向 | 内容 | 对应决策 |
|---|---|---|---|
| `match_card` | 双向 | 一阶名片（L1 可见；L2/L3 密文随卡携带） | D5、D8 |
| `card_renewal` | 双向 | 重签名片（version+1） | D3 |
| `upgrade_request` | 单向 | 升级请求封：申请解锁 L2，附本人 `match_card` | D5、D8 |
| `grant_l2` | 单向 | 解锁授权：携带用对方公钥加密的 key_L2 | D5 |
| `topic_pack` | 单向 | 考题包：1 主题（≤2 追问），标注出题方与理由 | D10、D11 |
| `answer_card` | 单向 | 回卷：结构化答案 / 带回问主人标记 / 婉答标记 | D10 |
| `graduation_invite` | 单向 | 毕业邀请封：亲笔短信（可选）+ 申请解锁 L3 | D13 |
| `grant_l3` | 单向 | 见面层解锁：逐字段 opt-in 的密钥交付 | D13 |
| `decline_silent` | 单向 | 婉拒回执：固定内容、不可携带任何信息（防侧信道）——v1 可选择"不回复"代替 | D4 |

## 5. 受控词表 v0.1（初版维度）

初版刻意克制（D10"少而精"原则），随版本迭代：

- **interests**：户外 / 运动 / 阅读 / 影视 / 音乐 / 美食 / 旅行 / 游戏 / 手工 / 宠物 / 摄影 / 学习成长（12 个起步）
- **values_tags**：家庭优先 / 事业进取 / 生活平衡 / 自由探索 / 稳定安稳 / 开放尝新 / 传统务实 / 精神成长（8 个起步）
- **dealbreakers 维度**：吸烟 / 饮酒 / 生育意愿 / 异地 / 宠物 / 债务 / 宗教 / 其他（结构化为维度+描述）
- **job_category**：技术 / 产品设计 / 专业服务（法财医教）/ 公务事业 / 经商自营 / 技能劳作 / 自由职业 / 其他

## 6. 密钥体系（v1 就建全，v2 零迁移的关键）

| 密钥 | 算法 | 存放 | 用途 |
|---|---|---|---|
| 身份密钥对 | Ed25519 | 私钥永不出设备 | 卡片与一切信封签名（防伪造，D13 反诈） |
| 加密协商 | X25519 | 公钥随 `match_card` 元数据交换 | **第一次握手 = 换卡即换公钥**；此后所有定向信封用收件人公钥 sealed box 加密对应层密钥 |
| 层密钥 key_L1/L2/L3 | AES-256-GCM | 本地生成 | 三层各自独立加密；grant 类信封只交付密钥不解密文（服务端/中转者全程只见密文） |

v1：全部在本地完成，无任何在线组件。v2：同一套格式上广场，服务端只存 `card_id + 公钥 + 密文 + TTL`——**零知识天然成立，格式零迁移**。

## 7. 校验与容错（写进协议规范 v0 的硬规则）

1. LLM 生成卡片后必须过 JSON Schema 校验，失败自动重试（≤3 次），再失败转人工确认——D7 风险②的落地
2. 未知字段一律忽略并告警（向前兼容）
3. `depth.completeness < 0.6` 的卡片，比对报告必须标注"对方画像深度不足，结论置信度有限"（D7 风险①）
4. 签名验证失败 = 整卡作废，不降级处理

## 8. 开放问题拍板记录（2026-10-14，孙超拍板，全部采纳产品合伙人建议）

1. **公开层加密与否** → **L1 也加密**：key_L1 随卡明文携带，广场场景爬虫拿不到结构化明文，格式三层统一，代价为零。
2. **income_band 收不收** → **保留，默认缺省**（留在 L2）：把选择权给主人。孙超同时提出"陌生人初筛需要经济信号"的真实需求，据此 **L1 新增 `econ_signal` 经济状态自述字段**（见 3.1）——用"生活状态"而非"收入数字"的形态满足初筛诉求，收入数字段仍默认留在 L2。
3. **受控词表首发维度** → **按第 5 节初版定稿**，随版本迭代扩充。
4. **decline_silent 婉拒回执** → **v1 不做**（"不回复"更静默）、**v2 做**（广场需要明确终止信号关闭轮次）。
