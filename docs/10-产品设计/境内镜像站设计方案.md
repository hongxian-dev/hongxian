## 1. 这个站是什么（以及不是什么）

### 1.1 表面理由与真实价值

**表面理由**：ICP 备案要求境内有一个真实可访问的网站，且内容必须与备案填报的「服务名称」和「备注」一致。服务名称已定为 **开源实战笔记**，备注为个人技术笔记语态，所以境内必须真的有一个技术笔记站。

**真实价值**：

| 价值 | 说明 | 可否替代 |
|---|---|---|
| **合规载体** | 备案、公安备案、后续年度核验，都需要这个站真实存在且内容匹配 | ❌ |
| **技术信任资产** | 一个陌生人凭什么信"零知识、不存你数据"？靠能读懂的技术文章，不靠口号 | ❌ |
| **国内搜索可见性** | `hongxian.dev` 在 GitHub Pages，百度收录极差；`hongxian.red` 是可正常收录的国内站 | ❌ |

> **一句实话**：这站的主要作用是"合法存在"。搜索流量是加分项，不是目标——目标读者池很小（会装 MCP、会读协议的中文开发者），不要按流量站的方式运营它。

### 1.2 双轨分工（不可混淆）

| | 境外站 `hongxian.dev` | 境内站 `hongxian.red` |
|---|---|---|
| 性质 | **产品官网** | **个人技术笔记** |
| 语态 | 第一人称产品叙事 | 第一人称开发者叙事 |
| 主体内容 | 理念、工作原理、Demo、信任清单、FAQ、赞助 | 技术文章 90% +「我的项目」10% |
| 红线的位置 | 主角 | **配角**——只在「我的项目」页出现 |
| 品牌视觉 | M1 月老 + 纸信版式 | **刻意剥离**——只有站名与红点，无吉祥物、无产品插画 |
| 婚恋/交友字样 | 可以 | **绝对不可以** |

> **一句话**：境外站是"作品"，境内站是"作者"。管局看到的应该是一个人在认真写技术笔记，顺手提到自己做了个项目——不是换皮的产品页。

### 1.3 明确不做的事

- ❌ 产品功能页、定价页、Demo 交互
- ❌ 注册、登录、评论、留言板、搜索后端
- ❌ "申请试用/联系我们/商务合作"入口
- ❌ 任何收款、赞助、赞赏、二维码（境内站零商业元素）
- ❌ 第三方统计（百度统计 / GA / 友盟）——与零追踪纪律冲突，也引发经营性联想
- ❌ 搬运境外站产品文案
- ❌ 友情链接交换
- ❌ 深色模式切换（笔记站全程亮底，减少复杂度）

## 2. 合规硬约束（违反即返工）

### 2.1 三条一票否决

| # | 约束 | 判定方式 |
|---|---|---|
| 1 | **站名逐字等于「开源实战笔记」** | 首页 `<title>` 前缀、页头站点名、页脚站点名三处完全一致；不得简写、不得加英文副名做主标题 |
| 2 | **全站无经营性表述** | 见 §2.2 P0 词表 |
| 3 | **全站无婚恋交友类词** | 见 §2.2 P0 词表 |

### 2.2 敏感词分级（开发按此写验收脚本）

| 级别 | 处理 | 词表 |
|---|---|---|
| **P0 硬失败** | 构建直接失败，不允许产出 | 婚恋、相亲、交友、征婚、脱单、彩礼、介绍对象、单身男女、会员、充值、付费、订阅、购买、下单、客服、商务合作、招商、加盟、优惠活动、入驻、赞赏、捐赠 |
| **P1 人工复核** | 出现需在 PR 说明理由 | 撮合、匹配（技术语境可，产品语境不可）、红线（项目名可，卖点不可）、月老（仅「我的项目」页，≤2 次）、找对象 |
| **P2 允许** | 无需处理 | 开源、协议、加密、密钥、服务端、客户端、部署、自托管、镜像、算法、架构 |

> `匹配` 判定标准是**主语**：「字段匹配」「正则匹配」可用，「帮你匹配到合适的人」不可。

## 3. 信息架构与 URL 规则

### 3.1 页面清单

| 页面 | URL | 产物文件 | 优先级 |
|---|---|---|---|
| 首页 | `/` | `index.html` | P0 |
| 全部笔记 | `/notes/` | `notes/index.html` | P0 |
| 文章页 | `/notes/<slug>/` | `notes/<slug>/index.html` | P0 |
| 我的项目 | `/projects/` | `projects/index.html` | P0 |
| 关于 | `/about/` | `about/index.html` | P0 |
| RSS | `/feed.xml` | `feed.xml` | P1 |
| 站点地图 | `/sitemap.xml` | `sitemap.xml` | P1 |
| 404 | `/404.html` | `404.html` | P1 |
| robots | `/robots.txt` | `robots.txt` | P1 |

**URL 规则**：
- slug 一律**英文小写 + 连字符**，不用中文、不用日期前缀（`/notes/key-as-identity/`，不是 `/notes/2026/10/24/密钥即身份.html`）
- 每个页面以目录形式输出（`xxx/index.html`），URL 带尾斜杠，便于 Nginx 直接 serve 且不产生 301 链
- slug 一经发布**永不变更**（变更必须留 301 重定向表）

### 3.2 导航与页脚（全站一致，文案定稿）

**页头**（左侧站点名，右侧三项导航）：

```
开源实战笔记·          笔记   项目   关于
```

- 站点名后的 `·` 是一个红色句点，不闪烁、不旋转（无动效）
- 当前页导航项：文字变墨色 `#1A1D23` + 底部 1px 红线；非当前页：`#6B7280`，悬停变墨色

**页脚**（三行，居中或左对齐均可，建议左对齐）：

```
开源实战笔记 · 一个工程师的技术笔记
© 2026 孙超 · 京ICP备XXXXXXXX号-1
RSS
```

- 「孙超」链接到 `/about/`；RSS 链接 `/feed.xml`
- 页脚无社交图标、无友情链接、无"Powered by"

### 3.3 首页结构（从上到下）

| 区 | 内容 | 规格 |
|---|---|---|
| 1 | 页头 | 见 §3.2 |
| 2 | 一句话自我介绍 | 定稿文案见 §4.1，正文 `max-width: 44rem` |
| 3 | 最新笔记列表 | 最多 10 篇，按日期倒序；每条 = 日期 · 标题一行 + 摘要一行 |
| 4 | 「全部笔记 →」文字链接 | 指向 `/notes/` |
| 5 | 页脚 | 见 §3.2 |

列表条目结构：

```html
<li class="note-item">
  <a class="note-title" href="/notes/key-as-identity/">用 Ed25519 加 X25519 替掉注册登录：密钥即身份的一种做法</a>
  <p class="note-summary">不存密码、不存手机号，把身份做成一对密钥——这种设计省掉了什么，又欠下了什么。</p>
  <div class="note-meta">2026-10-24 · 约 14 分钟 · 密码学</div>
</li>
```

> 顺序注意：**标题在前、元信息在后**（与常见博客相反）。理由是列表主要被扫读标题，日期不是决策依据。

### 3.4 全部笔记页（`/notes/`）

按年份分组，年份为 h2（左侧红线锚点），组内按日期倒序，结构同首页列表。年份之间无分隔线（靠 h2 间距区分）。不放分页——文章数在 20 篇以内时不需要，超过再谈。

### 3.5 文章页

```
[页头]

2026-10-24 · 约 14 分钟 · 密码学        ← .article-meta，等宽 12.5px
<h1>标题</h1>
[摘要段落，可选，用 .lede 样式，18px，颜色略浅]

[正文 h2 / h3 / p / pre / blockquote / ul]

─────────────
写于 2026-10-24                          ← .article-foot
← 上一篇：xxx      下一篇：xxx →          ← 跨年边界可只显示一侧
```

- 正文层级最多到 h3
- `h2` 左侧 3px 红线（`border-left: 3px solid #C8102E; padding-left: 12px`）
- 代码块：`overflow-x: auto`，不折行，标语言，背景 `#F4F2EC`，无阴影
- 行内代码：`#F4F2EC` 底 + 等宽字，`border-radius: 2px`，无边框
- 引用块：左侧 3px 灰线（`#E5E1D8`），文字 `#4B5563`，不加引号装饰
- 表格：仅上下列线（`border-top/bottom: 1px solid #E5E1D8`），表头 `font-weight: 600`，单元格 `padding: 8px 12px`
- 图片：同源相对路径，`max-width: 100%`，无边框无圆角无阴影；必须写 `alt`

### 3.6 我的项目页（`/projects/`）

结构固定为四段（内容见 `境内站内容/pages/projects.md`）：

1. 一句话技术定位（不是产品 slogan）
2. 事实表：项目名 / 技术定位 / 开源协议 / 代码仓库 / 协议版本 / 当前状态
3. 三个技术要点（各 2–3 行，纯技术描述）
4. 边界声明（一段，冷语气）+ 一处指向 `hongxian.dev` 的文字链接

> **纪律**：项目页是全站唯一允许出现"红线""月老"的地方；不得写"解决什么问题""为什么做这个"，只写"这是什么技术"。

### 3.7 关于页（`/about/`）

四段：我是谁（3–4 句）· 我在做什么（技术方向）· 这个站写什么（内容承诺）· 怎么联系（邮箱 + GitHub，**不放手机号、不放微信**）。

## 5. 内容模型（front-matter 契约）

### 5.1 文章 front-matter

```yaml
---
title: 用 Ed25519 加 X25519 替掉注册登录：密钥即身份的一种做法
slug: key-as-identity
date: 2026-10-24
summary: 不存密码、不存手机号，把身份做成一对密钥——这种设计省掉了什么，又欠下了什么。
tags: [密码学, 协议设计]
minutes: 14
draft: false
---
```

| 字段 | 必填 | 规则 | 校验 |
|---|---|---|---|
| `title` | ✅ | 中文标题，≤40 字，不用惊叹号与问号堆叠 | 长度校验 |
| `slug` | ✅ | `^[a-z0-9]+(-[a-z0-9]+)*$`，与文件名无关但唯一 | 正则 + 唯一性 |
| `date` | ✅ | `YYYY-MM-DD` | 格式 |
| `summary` | ✅ | ≤60 字，列表页展示 | 长度 |
| `tags` | ✅ | 1–3 个，纯文字，不生成标签页 | 数量 |
| `minutes` | ✅ | 整数，按每分钟 350 字估算 | 数字 |
| `draft` | ❌ | 默认 false；true 则不进列表、不进 RSS、不进 sitemap | — |

### 5.2 构建产物结构

```
dist/
├── index.html
├── notes/index.html
├── notes/<slug>/index.html        × N
├── projects/index.html
├── about/index.html
├── 404.html
├── feed.xml
├── sitemap.xml
├── robots.txt
└── assets/
    └── (文章配图，同源相对路径；无则空)
```

**CSS 处理**：内联进每个 HTML 的 `<style>`（单文件备份友好），不产出外部 `.css`。CSS 总量控制在 8 KB 内。

### 5.3 内容目录约定

```
content/
├── notes/<date>-<slug>.md         # 每篇一个文件
└── pages/
    ├── home.md                    # 首页自我介绍（或直接写进模板）
    ├── about.md
    └── projects.md
```

写作时只碰 `content/`，不碰模板与样式——这是"能不能坚持写三年"的分水岭。

| 页脚 | `border-top: 1px solid var(--line); margin-top: 64px; padding: 24px 0 40px;` 字号 13px，颜色 `--ink-3` |
| 移动端 | `<640px`：`font-size: 16px`，容器 `padding: 0 18px`，`h1: 24px`，`h2: 19px` |

### 6.3 禁项（宪法 §11）

禁渐变、禁投影、禁毛玻璃、禁圆角（`border-radius` 仅行内代码允许 2px）、禁动效（无 `transition` 超过 120ms、无 `animation`）、禁深色版面、禁 webfont、禁图标字体。
