## 篇一：三十岁以后，认识一个新朋友的成本

### 文件

`01-cost-of-meeting-people.md`

### 核心

不是"人变得孤僻了"，是**交友的三个来源在同一时间段同时枯竭**：同学分散、同事流动、兴趣社群只提供"见过"不提供"相处"。再叠加时间预算的真实变化。这一篇只描述机制，不给解法。

### 关键论证

| 来源 | 二十几岁时 | 三十岁后 |
|---|---|---|
| 同学 | 同城同校，天天见 | 分散在不同城市，群里五年没动静 |
| 同事 | 同龄人多，加班一起吃夜宵 | 层级分化，跳槽一次断一批 |
| 兴趣社群 | 打球、桌游、读书会，每周都有局 | 还去，但只认识"脸熟的人"，加完微信没有然后 |
| 偶遇 | 宿舍楼下、食堂、通勤 | 通勤是唯一剩下的场合，而通勤不说话 |

结论：**不是社交意愿下降，是"重复见面"的机会消失了**。友谊需要重复见面，重复见面需要共同场景，而成年后所有共同场景都在减少。

## 篇二：条件都对，为什么聊不下去

### 文件

`02-conditions-dont-talk.md`

### 核心

条件的对等 ≠ 相处的可能。条件是"可以陈述的自我"，而相处依赖大量"不可陈述的部分"。这一篇不做价值判断，只描述一个信息结构问题：**高维的东西被压成了一维的清单。**

### 关键论证

- 两个条件表几乎完美对齐的人，见面两小时冷场三次
- 另一对条件差得离谱（学历、行业、家庭背景全不同），聊到餐厅打烊
- 原因不是"感觉"这么玄：真正决定相处体验的是节奏、对什么敏感、什么时候沉默不尴尬、笑话的落点——这些都写不进条件表
- 而相亲这个场景的结构性问题在于：**双方都在演示，而不是在生活**。演示状态下，所有人都会表现成"条件表里那个人的加强版"
- 结论：不是人不会选，是**用来选的信息形态错了**

## 篇三：我为什么不做撮合

### 文件

`03-why-not-matchmaking.md`

### 核心

我也动过"我认识两个人都挺合适，要不要介绍"的念头，然后发现这个念头让我不舒服。讲清为什么，以及最后为什么选择做工具而不是做服务。

### 关键论证

1. **介绍人会成为关系的责任人**。成了要居功，不成要被怨，而中间那些说不清的摩擦最后都落到介绍人身上。
2. **撮合意味着替别人做判断**，而做判断需要的信息我根本拿不到——我不知道他们半夜吵架时是什么样子，也不知道对方怎么对待服务员。
3. 更根本的一条：**判断这件事不该外包**。哪怕 AI 判断得比我准，最终要和这个人过日子的也不是 AI。
4. 所以我选了一个看起来更笨的方案：做工具，让双方的 Agent 交换加密信息，人自己决定。工具不排序、不推荐、不撮合，只做传输。
5. 代价要说清楚：**工具比服务难用**。用户得自己装、自己填、自己判断。这条路注定比"填写资料等推荐"慢。

### 需要孙超替换的真实细节

文中以下位置用了概括写法，替换成你自己的记忆会明显更有说服力：

1. 篇一：具体是哪一年、哪个城市、哪个群突然安静了
2. 篇一：兴趣社群去了几次、加了几个人、后来怎么没联系了
3. 篇二：那对"条件表对齐但冷场"的朋友，是什么场合认识的（不必写名字）
4. 篇二：那对"条件差很远但聊到打烊"的，聊了什么
5. 篇三：那个"要不要介绍"的念头，最后你有没有介绍

> **原则**：宁可写得含糊，不要编造具体故事。编造出来的细节读者能感觉到，而且一旦被问就崩。
