## front-matter 契约

每篇文章头部：

```yaml
---
title: 标题（≤40 字）
slug: 英文小写连字符（唯一，发布后永不变）
date: YYYY-MM-DD
summary: 一句话摘要（≤60 字，列表页展示）
tags: [标签, 标签]        # 1–3 个，不生成标签页
minutes: 整数             # 按 250 字/分钟估算（技术文含代码，读速低于普通文章）
draft: false
---
```

字段规则与校验见设计方案 §5.1。**`slug` 一旦发布不得变更**（会破坏链接与外部引用）。

## 内容纪律（写新文章时必须遵守）

1. **不出现 P0 词**：婚恋、相亲、交友、征婚、脱单、彩礼、会员、充值、付费、订阅、购买、下单、客服、商务合作、招商、加盟、优惠活动、入驻、赞赏、捐赠
2. **项目只在文末轻提一次**，句式固定为"这是我做的一个开源项目里的做法"，不带链接、不做号召
3. **代码必须标"示意"**，除非是从仓库逐字摘的
4. **不写"我们"**，写"我"——个人站的语态
5. **不用感叹号**，不写"震惊""必看"这类标题词
6. **诚实优先于好看**：每篇至少有一处"这个方案不适合什么"或"我踩过的坑"，这是这个站和营销号的区别

## 重要：本文件的词表段不要拷进 `content/`

上面「内容纪律」一节为了给验收脚本提供词表，**逐字列出了 P0 敏感词**。这段文本如果被拷进 `content/`，验收脚本会把词表本身扫成命中。

处理方式：

- 只拷 `notes/` 与 `pages/` 里的正文，**不要拷 `README.md`**
- 验收脚本的扫描范围限定为 `dist/`（构建产物），不要扫源目录
- 词表建议在脚本里定义一次（常量数组），不要在代码注释里重复写

已实测：`notes/` + `pages/` 的正文 P0 命中 = 0（首轮扫出 1 处"客服"，已改写）。
