## 0. 一句话

**我们看不到你的内容，但我们必须告诉你能看到什么。**

这份声明不是免责条款，是一份清单：哪些数据在你手里、哪些在我们手里、哪些会被别人看到。凡是做不到「不收集」的，我们逐条写清为什么收集、怎么存、多久删。

## 1. 数据在哪：三个位置，别混

| 位置 | 存什么 | 谁能看到 |
|---|---|---|
| **你的设备**（`~/.hongxian/`） | 画像、匹配卡、红线手账、见面复盘、L3 明文 | 只有你。我们没有任何访问通道 |
| **我们的平台**（首尔服务器） | 三层加密后的密文信封、公钥档案、假名公钥的操作记录、匿名聚合计数、**手机号哈希（仅贴广场者）** | 我们（但解不开内容） |
| **你的 AI 客户端所连的模型服务** | 你在对话里给出的信息、月老为你生成的内容 | 该模型服务商。**这是本项目唯一无法控制的数据流**，见 §6 |

---

## 2. 我们收集什么（逐项，无兜底条款）

| 数据 | 为什么 | 形式 | 保存期 |
|---|---|---|---|
| 身份公钥（Ed25519）/ 加密公钥（X25519） | 让别人能给你投递加密信封 | 明文公钥 | 至你注销 |
| 加密后的卡片与信封 | 平台只做转发与暂存（像邮局） | **AES-256-GCM 密文，我们无密钥** | 信封按保留期自动清理；卡片至你撤卡 |
| 假名公钥的操作记录 | 限速、防滥用、举报处置 | `opaque_id` + 时间 + 动作类型 | 90 天 |
| 匿名聚合计数（opt-in） | 公开透明页：多少条姻缘线在跑 | 只有总和，无任何个体标识 | 永久（不可逆聚合） |
| 行为分析数据（opt-in） | 改进产品：使用频次、功能路径、设备类型 | 绑定假名 ID，**不含任何真实身份字段** | 180 天 |
| **邮箱哈希** | **仅用于贴卡上广场前的发布者确认** | `HMAC-SHA256(标准化邮箱, 服务端盐)`，**不存明文** | 至你解绑或注销 |
| 举报记录 | 处置滥用与诈骗 | 加盐假名 + 独立人数计数 | 至处置完毕 |

### 2.1 我们明确**不**收集

- ❌ 姓名、身份证号、护照号、人脸、照片
- ❌ **手机号**（连这个都不需要——发布确认用的是邮箱）
- ❌ 精确住址、精确收入、工作单位名称
- ❌ 聊天记录、通话记录、通讯录
- ❌ IP 地址（除短时反滥用风控，分钟内丢弃、不留存、不用于分析）
- ❌ 你的位置轨迹
- ❌ 你在其他平台的账号

> 我们也不会用「为了提供服务所必需」这类模糊表述去兜住以上任何一项。

## 3. 四环隔离（这是架构，不是承诺）

| 环 | 存什么 | 隔离规则 |
|---|---|---|
| **内容环** | 加密的卡片与信封 | 平台无解密密钥。改代码也解不开 |
| **聚合环** | 只有总和 | 不存任何个体 ID，不可反推 |
| **行为分析环**（opt-in） | 频次 / 路径 / 设备类型 + 假名 ID | 禁与真实身份关联 |
| **身份凭据环**（仅贴广场者） | 邮箱哈希 ↔ 假名公钥 | **永不与其他三环做任何关联**；不用于排序、推荐、画像、广告 |

四环之间**不做 join**。这条是硬约束：即使将来有人要求我们「关联一下」，技术上也没有现成的关联字段。

## 4. 发布确认：唯一需要「联系方式」的一步，单独说明

**只有一件事需要一个邮箱：把卡贴到「红线广场」——一个公开可见的列表。**

**先说一句不好听的实话：这不是实名认证。** 我们确认的是「这个邮箱能收到信」，不是「你是谁」。《网络安全法》第 26 条对公开发布信息要求的是发布者的真实身份信息认证，**我们目前做不到那一层，所以我们不声称做到了**。这一步的价值只有一个：让广场上的每个发布者都有一个可追溯、可处置的联系点，而不是一个凭空出现的假名。

| 问题 | 答案 |
|---|---|
| 是账号吗 | **不是。** 不能登录、不能找回密码、不能替代 24 词恢复短语 |
| 会出现在卡片里吗 | **不会。** 任何界面、任何信封、任何报告都不出现 |
| 怎么存 | 只存 `HMAC-SHA256(标准化邮箱, 服务端盐)`。**库里没有明文邮箱** |
| 验证时会怎样 | 你提交邮箱的**那几秒内**，明文存在于服务端内存用于发信与比对，随后立即丢弃；**不写日志、不入库** |
| 一个邮箱能绑几个身份 | 一个。换身份需先解绑 |
| 不验证行不行 | 行。**不收卡、不上广场、只和认识的人换卡，全程不需要邮箱** |
| 能解绑吗 | 能。解绑后失去贴卡能力，历史卡片保留、不追溯下架 |
| 为什么不用手机号 | **个人主体开不了国内短信签名**（2025-09-18 起运营商不接受个人签名报备）。等有了经营主体，会升级为手机号验证 |
| 邮件进垃圾箱怎么办 | 会。我们配好 SPF / DKIM / DMARC，但仍建议检查垃圾箱，或改用 Gmail / 163 |

**必须说清的一件不好听的事**：如果执法机关依法调取，我们**能**提供「某个假名公钥对应某个邮箱哈希」。如果你的邮箱本身可反推真实身份（例如用实名手机号绑定的邮箱、或邮箱前缀就是真名），这层保护会相应减弱。**这一环是「可追溯」，不是「匿名」**——我们不会假装它更强。

**升级承诺**：一旦取得经营主体，发布确认将从邮箱升级为手机号（法定认证方式之一）。届时提前 14 天公示，并给现有发布者留过渡期。

## 5. 数据存在哪，出境意味着什么

- **平台服务部署在韩国首尔**（腾讯云轻量），不在中国境内。
- 因此你的数据构成**数据出境**。这是事实，需要告知你。
- 出境的数据**是密文**：平台没有解密密钥，出境内容对我们而言不可读。
- **邮箱哈希也在此列**（仅贴广场者）。它不可逆推邮箱，但它确实出境了。
- **邮件服务商在境外**：发验证码时，你的邮箱地址会经 **Resend**（美国公司，发信节点位于 AWS 东京 `ap-northeast-1`）的服务器，这是第二层出境。若不接受，就不要贴卡——其余功能完全不需要邮箱。
- 为什么不放境内：本项目由个人维护、非经营性，境内部署需 ICP 备案且与「免费公益」定位存在制度摩擦；境外部署是当前唯一在合规上可行的选择。

## 6. 第三方与你的 AI 客户端（这一条最重要）

月老不是独立 App，它运行在**你自己的 AI 客户端**里。这意味着：

| 第三方 | 会看到什么 | 我们能否控制 |
|---|---|---|
| **你的 AI 客户端所连的模型服务商** | 你在对话里输入的一切（包括访谈内容、画像片段、报告原文） | ❌ **不能**。这是宿主决定的，不是我们 |
| **邮件服务商：Resend**（美国公司，发信节点 AWS 东京 `ap-northeast-1`，发信域 `mail.hongxian.dev`） | 你的邮箱地址、邮件标题与验证码内容、投递状态事件（仅贴广场时） | ❌ 不能。委托发送，必须告知。其保留策略依其自身条款 |
| 对象存储（数据备份） | 平台侧信箱数据的加密副本 | ✅ 只能看到密文 |

**关于模型服务商，请你自己判断**：你选择了哪家模型、数据是否出域、是否用于训练，由你与该服务商之间的关系决定。月老只保证「不主动外发」——它不调用任何模型的 API，推理由你的宿主承担，我们零 API Key、零模型依赖。

**建议**：如果你对某段内容敏感，不要在对话里说出来。画像与报告的详细度，你自己控制。

## 7. 你随时可以做的四件事

| 权利 | 怎么做 | 效果 |
|---|---|---|
| **导出** | `export_card` / `backup` | 全部本地数据打包给你 |
| **删除（本地）** | `wipe` | 本地数据清零，不可恢复 |
| **注销（平台）** | 客户端发起注销 → 平台级联删除 | 公钥档案、信箱数据、号码哈希一并删除 |
| **退出行为分析** | 首次启动或设置中随时关闭 | 关闭后不再上报，已上报的匿名数据因不可逆而无法删除 |

**注意**：已解密发出的 L3 明文**无法撤回**。你授权那一刻，对方就拿到了。这是密码学事实，不是产品缺陷。
