# 安装与信任指南

> 本指南面向想自己动手验证、排错、备份与删除的月老用户。全文约 15 分钟读完。
> 想看产品是什么，先读 [README](../README.md)（中文）或 [README.en](../README.en.md)（English）。

## 1. 系统要求

| 项 | 要求 | 说明 |
|---|---|---|
| 运行时 | Node.js ≥ 20（推荐 22 LTS） | 纯 JS + WASM 实现，无原生编译，装完即用 |
| 磁盘 | < 50 MB | npm 包约 10 MB；数据目录每用户通常 < 5 MB |
| 操作系统 | Windows / macOS / Linux | 数据目录 `~/.hongxian/`（Windows 为 `%USERPROFILE%\.hongxian`） |
| 宿主 | 任一标准 MCP 宿主 | 见 [宿主兼容性矩阵](host-compatibility.md)；**手机 App 不支持** |

不需要：账号、注册、手机号、API Key、信用卡。

## 2. 安装（两条路，产物完全相同）

### 方式 A：npx 一行（推荐）

```bash
npx -y @hongxian/mcp
```

宿主配置：

```jsonc
{
  "mcpServers": {
    "yuelao": {
      "command": "npx",
      "args": ["-y", "@hongxian/mcp"]
    }
  }
}
```

首次调用会把包装进 npm 缓存，之后启动约几百毫秒。想先确认它能跑起来：

```bash
npx -y @hongxian/mcp < /dev/null   # 打印「月老已上线（STDIO，零服务端依赖）。21 件工具 + 8 条指引就绪。」即成功
```

### 方式 B：全局安装（调用频繁，省一次 npx 解析）

```bash
npm install -g @hongxian/mcp
```

宿主配置改为 `command: "hongxian-mcp"`（不带参数）。

### 方式 C：从源码构建（不想跑一个自己没编译过的二进制）

```bash
git clone https://github.com/hongxian-dev/hongxian.git
cd hongxian
npm ci          # 严格按 lockfile 安装
npm run build   # 一步 tsc，无打包器
npm test        # 372 个单元测试（31 个文件）
npm run e2e     # 125 项 MCP 端到端断言
npm run smoke   # 21 项宿主级冒烟：真子进程 + 真 STDIO JSON-RPC
```

跑完这些，你就用自己的机器验证了「这套代码确实能起来、确实只做它说的事」。

然后宿主配置指向本地构建产物：

```jsonc
{
  "mcpServers": {
    "yuelao": {
      "command": "node",
      "args": ["<绝对路径>/hongxian/packages/mcp/dist/index.js"]
    }
  }
}
```

## 3. 首次启动：知情同意与恢复短语

对宿主 Agent 说 **"打开月老"**，它会先出示一页知情同意（未确认前，任何涉及画像的工具都不会执行）。全文如下——这也是写入 `consent.json` 的五条承诺：

> 一、我是什么。我是住在你设备里的一个工具，帮你把相亲里那些重复的、难为情的、耗时间的过程变得轻省。我不会替你心动，也不会替你做主。
>
> 二、你的数据存在哪。你的画像、你签发的每一张卡、往来的一切记录，全部只存在你这台设备上（`~/.hongxian/` 目录）。我们没有服务器，也不登录任何账号。你可以随时让我把这一切删得干干净净。
>
> 三、对话会经过什么。我和你聊天时，这些话会经过你在这台设备上配置的模型来处理。如果你配置的是云端模型，这些内容会发送给对应的服务商——这是你需要知道的，我不会说"只有我知道"这种便宜话。
>
> 四、有一件事无法回头。当你和某人互相解锁到见面层（联系方式、真实姓名），交给对方的明文，我没有办法远程收回——这是点对点的架构决定的。所以每一阶的解锁，都请你自己确认。
>
> 五、年龄。使用本工具需要你已年满 18 周岁。

确认后生成 **24 词中文恢复短语**（BIP39 词表，一次性完整展示 + 强制逐词确认）：

- 短语 = 你的身份。Argon2id 派生全部密钥；**换设备靠它重建同一身份**（对方眼里的你还是你）。
- 丢失 = 身份不可恢复（设计如此，任何服务器都救不了——因为我们没有服务器）。
- 建议：纸质抄写 + 与加密档案分开保管。月老不会替你保存，也无处保存。

## 4. 数据目录说明（`~/.hongxian/`）

```
~/.hongxian/
├── consent.json                     # 知情同意记录（含 ≥18 承诺与时间戳）
├── settings.json                    # 本地设置（opt_in_counter 计数开关，默认关；plaza_instance 服务端地址）
├── keys/                            # 密钥文件——全部加密，无任何明文私钥
│   ├── id.enc                       #   身份密钥对（Ed25519）
│   ├── kx.enc                       #   协商密钥对（X25519）
│   └── lk.enc                       #   层密钥 key_L1 / L2 / L3
├── profile/
│   ├── interview-state.json         # 三阶访谈状态机 + 画像
│   └── completeness.json            # 完整度评分（驱动追问策略）
├── cards/
│   ├── mine/                        # 你签发的卡（含已导出历史）
│   ├── plaza-mine/                  # 你贴上广场的卡（plaza_card 变体——无 key_l1）
│   ├── plaza/<对方 keyId>/          # 广场浏览存证（grant_l1 到来时解密一阶用）
│   └── contacts/<对方 keyId>/       # 导入的对方卡与往来信封
├── lines/<对方 keyId>/state.json    # 姻缘线（轮次状态机：考题包/回卷/毕业）
└── server/                          # 广场服务连接状态（仅当你连了服务端才有）
    ├── registration.json            #   自声明身份注册记录（opaque_id 等）
    ├── plaza-seen.json              #   已浏览轮廓（去重，500 条环形）
    └── pulled.json                  #   已拉取信封（幂重）
```

几点说明：

- **整个目录就是你的全部数据**。没有第二个副本，也没有我们这边的副本。可以整体拷进你自己的云盘做备份。
- **`cards/` 与 `lines/` 下的对方内容一律视为不可信数据**：月老读取后包裹数据标记、与指令隔离，报告引用只走 schema 字段白名单（防 prompt 注入）。
- **目录位置可用 `HONGXIAN_HOME` 环境变量覆盖**（便携盘/测试场景）。进程内所有路径经归一化校验，拒绝越出数据目录的写入。
- **原子写入**：所有文件先写临时文件再 rename，不会留下半截文件。

## 5. 备份与恢复（换设备不掉线）

**备份**：对 Agent 说"备份我的数据"（`backup` 工具）。你会得到一份 `hongxian-backup.json`——用你当前恢复短语加密的画像/卡片/手账/设置快照。把它存进你自己的云盘。

> 档案**不含**密钥：密钥即身份，走恢复短语。档案与短语任何一方单独泄露，都不足以还原你的数据。

**恢复**（新设备）：装好月老 → 对 Agent 说"恢复我的数据"，提供档案全文 + 24 词短语。密钥文件由短语重建，画像/卡片/手账写回本机。

**日常多设备**：也可以直接把整个 `~/.hongxian/` 目录拷到另一台设备（密钥文件随目录走）。两条路都通，前者更适合云盘，后者更适合局域网对拷。

## 6. （可选）连接广场服务：让陌生人也能发现你

v1 的交换靠"递文件"——只对熟人链成立。想让陌生人也可能发现你，可以连一个**广场服务**（v2 的消息服务参考实现，`packages/server`）。这是可选的：不连，一切功能原样可用。

**一分钟自托管**（推荐姿势——服务端是你自己的）：

```bash
git clone https://github.com/hongxian-dev/hongxian.git
cd hongxian/packages/server
docker compose up -d        # 起在 127.0.0.1:8787，数据在 ./data
```

然后对 Agent 说：**"月老，连接广场服务 http://127.0.0.1:8787"**（任意广场工具带上这个地址即可，月老会记住它，之后不用每次带）。

**连上之后多出五件事**：

| 你说 | 发生什么 |
|---|---|
| "贴一张广场卡" | 你的匹配卡派生为**广场卡变体**（自动剥掉一阶钥匙）贴上服务端——陌生人从此能看见"你在"，但看不到任何内容。贴之前月老会逐项念出你这次公开了哪些检索条件（城市/年龄段/性别/可见范围），确认才发 |
| "看看广场上都有谁" | 拉取全量卡池，本地验签过滤——只见轮廓（编号、公钥、有效期），内容一律不可见。想只看同城/同年龄段，就明确声明条件；不声明就是看全量 |
| "对这个人感兴趣" | 经服务端递一封敲门信——你只会知道"已入信箱"，对方读没读、想没想，**服务端不呈报、月老不假装知道** |
| "看看有没有信" | 拉你自己的信箱——拉取即从服务端删除（POP3 式），没有推送，没有"叮"的一声 |
| "这个人不对劲" | 举报到服务端——只收**受控理由码**（骚扰 / 垃圾信息 / 疑似诈骗 / 冒名 / 其他），不收自由文本（避免举报变成内容审查通道）；举报人身份存加盐假名，**3 个独立举报**才标记；标记结果只有被举报者本人能查 |

**服务端能看到什么**：你的公钥、编号、和加密 blob。**看不到什么**：任何一层明文——一阶钥匙不在广场卡上（协议硬规则，服务端代码有测试断言拒收），解锁是对方显式授权动作。数据目录随时可以 `cat` 自己查。

**删除的连带效应**：`wipe` 会先尽力注销服务端身份（级联删服务端上的密文）再删本地；失败不阻塞本地删除，服务端残留按 30 天 TTL 自动清扫。

## 7. 删除（一键删净，无残留）

对 Agent 说：**"月老，删除我的全部数据"**（`wipe` 工具，需确认 `confirm=true`）。整个数据目录删除并返回清单——E2E 断言磁盘零残留。

也可以手动删：退出宿主后直接删除 `~/.hongxian/` 目录，效果等同（月老没有别处存任何东西）。

> 删除不可恢复；身份随密钥一同消失。已经解锁交给对方的明文无法撤回——这是知情同意第四条，开始就说清的。

## 8. 信任清单：你可以自己验的五件事

| # | 验证什么 | 怎么做 |
|---|---|---|
| 1 | **源码可信** | 全仓库可读：[schema](../packages/schema)（协议契约）、[crypto](../packages/crypto)（密钥体系）、[core](../packages/core)（领域逻辑）、[mcp](../packages/mcp)（月老本体）。构建只有一步 `tsc`，无打包混淆——"读到的即运行的" |
| 2 | **出网为零** | 安装后断网，除 opt-in 计数（默认关）外全部功能完整可用。想抓包佐证：关掉计数器后运行全程，除本地回环外无任何连接 |
| 3 | **产物与源码对得上** | 想完全不信任发布物就走方式 C：`npm ci && npm run build` 在你本机编译，产物来自你眼前的源码，中间没有第三方。`npm run verify` 一条命令跑完单测 + MCP E2E + server E2E + 宿主冒烟。走 npx 的话，`npm view @hongxian/mcp` 可查版本；**provenance 自 0.1.1 起才有**（0.1.0 首发是维护者本地发布的，这一点不粉饰） |
| 4 | **删除彻底** | `wipe` 工具返回删除清单；或手动删目录后全局搜索 `.hongxian-card`、`hongxian-backup` 均无残留 |
| 5 | **密码学实现** | 只用可审计的纯 JS/WASM 库（@noble 系 + hash-wasm）：Ed25519 签名、X25519 密钥封装、AES-256-GCM、Argon2id(t=3, m=64MB, p=4)。算法与参数在 [协议规范 §6](protocol-v0-spec.md) 公开，欢迎同业复算 |

## 9. 排错

见 [宿主兼容性矩阵 §3](host-compatibility.md#3-通用排错)——看不到工具、ENOENT、首次超时、Windows 中文路径等常见现象都有对应处理。

## 10. 可选的那个计数器（默认关闭）

月老内置一个 opt-in 匿名计数器（开启后，在签卡/导卡/发起交换时向公开计数器 POST 一条 `{metric, bucket}`，两者都只限受控词表白名单——无任何用户 ID、无设备指纹）。**默认关闭**（`settings.json` 的 `opt_in_counter: false`），可随时改回 `false`；关闭时零出网，失败静默不重试。为什么要有它、它不是什么，见产品 PRD §8（内部文档，不随仓库分发；设计口径：网站计数器性质，非用户追踪）。
